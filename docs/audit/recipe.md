## 1. Architecture at a glance

- **Stack:** TypeScript ~6.0 strict, Expo SDK 58, React 19.3 with the React Compiler (`app.json` `experiments.reactCompiler`), React Native 0.88, react-native-web 0.21, expo-router with typed routes. Chain: `@stellar/stellar-sdk` 17.4 (Soroban RPC and XDR), `@noble/curves` (ed25519 on native), WebCrypto Ed25519 (web), `react-native-passkeys` 0.4.2 (passkey creation only). Storage: `expo-secure-store` (native), `localStorage` and IndexedDB (web). Tests: `node --test` on pure `.ts` modules.
- **Added since `8ecf7ae`:** `@sentry/react-native` (crash + CTX 5xx reporting, `ops/error-reporting.ts`, scrubbed by `ops/sentry-scrubber.ts`), `expo-updates` (OTA, `runtimeVersion: fingerprint`, `checkAutomatically: NEVER`, app-driven check and critical reload in `updates/*`), `expo-local-authentication` (opt-in app lock), `expo-apple-authentication` + `@react-native-google-signin/google-signin` (ID token → CTX `/login/oauth`), `@react-native-async-storage/async-storage` (unencrypted on native, `localStorage` on web: wallet pin, sent-payment records, favourites), `@expo/fingerprint`.
- **Topology:** one client process per device or browser tab. `app.json` `web.output: "server"` means a web deploy ships an Expo server bundle; hosting is not configured here. In-process guards (refresh single-flight, `InFlightPayments`, poll generation counters, `ReloadGate`) are per process. Cross-tab guards exist on web only via `navigator.locks` (`token-store.web.ts` `exclusive`, `ctx/payment-lock.web.ts`) and fall back to no lock when `navigator.locks` is absent; native `paymentLock` and `tokenStore.exclusive` are no-ops. Two devices remain independent actors; only CTX serialises them.
- **Authority per entity:**
  - **CTX spend-api** (`src/ctx/client.ts`): users, sessions, merchants, gift-card orders, payments, cashback, wallet links.
  - **Stellar (Soroban):** the user's OZ smart account, token balances (SACs) and DeFindex vault shares. Read by RPC simulation (`src/stellar/soroban.ts`); the app never submits transactions itself.
  - **Device:** refresh token, device signer secret and public key. Access token in memory (`client.ts:190`).
- **External integrations and trust:**
  - **CTX** (`EXPO_PUBLIC_CTX_API_URL`): semi-trusted. Sponsor, relayer, pricer, order book. Builds every transaction the user signs. Design rule: never sign what CTX built without decoding and pinning it (`wallet/sponsored-call.ts`, `smart-wallet.ts:165-212`). Trusted for prices, order state, cashback, codes; not trusted for destinations, call shape or wallet code. CTX re-validates the call at sponsor time (annex), which protects against a broken app, not against a hostile CTX.
  - **Soroban RPC** (`network.rpcUrl`): trusted without a second source. Every chain-side check (wasm hash, context rules, vault value, tx outcome) reads through it. Mainnet uses a third-party provider.
  - **Pinned contracts** (`src/stellar/network.ts`): account wasm hash, WebAuthn and ed25519 verifiers, payee G-address, token SACs, USDC vault. `factory` (lines 22, 37, 55) and `usdc` (28, 48, 65) are pinned but never read.
  - **OS services:** passkey providers, biometrics, clipboard, screen capture, in-app browser.
  - **Friendbot** (testnet only, `smart-wallet.ts:101-109`).
- **Seams where interaction bugs concentrate:**
  1. `ctx/client.ts` → `wallet/smart-wallet.ts` → `wallet/sponsored-call.ts` → device signer → CTX sponsor. Every `BuiltTransaction` field crosses here.
  2. Key lifecycle: `device-signer(.web).ts`, `passkey.ts`, CTX deploy (idempotent per user, ignores new keys) and the on-chain context rules.
  3. Pay state machine: `components/gift-card-purchase.tsx` ⇄ `ctx/payment-state.ts` ⇄ CTX order status ⇄ chain tx status. Four sources of truth for "did I pay".
  4. Session: `session/token-store` ⇄ `client.ts` refresh ⇄ CTX rotation with a 30 s reuse window.
  5. Platform splits: web variants hold weaker key custody and token storage behind the same interface.

## 3. Money flows

MNY is the top-weighted dimension. Every flow ends in a CTX call or a chain transaction built by CTX.

- **Ingress to the wallet:**
  - **External deposit** to the smart-account C-address shown as "Deposit address" (`index.tsx:161`). Most exchanges cannot send to a C-address; the UI does not say so.
  - **Cashback** after fulfilment. CTX calls it a ledger transfer `system:giftcard` → user wallet; whether that is on chain or CTX-internal is unresolved (annex §Cashback). With `cashbackDestination: savings`, CTX gifts vault shares. The app displays `cashbackAmount/Credited/Reversed` only.
  - **Friendbot** (testnet).
- **Egress:**
  - **`pay`:** SAC `transfer(wallet, M-address, amount)`. CTX builds it with a per-payment muxed destination whose id is the low 8 bytes of the payment UUID. Pinned by `requirePayment` (`smart-wallet.ts:165-180`): contract = pinned SAC for `paymentCryptoCurrency`, method `transfer`, 3 args, `from` = wallet, base account of `to` = `network.payee`, amount = `units.parse(giftCard.paymentCryptoAmount)`. Not pinned: the muxed id, so which order the payment credits is CTX's choice.
  - **Refund / reversal:** operator-triggered on CTX. A refund reverses cashback "from the user's wallet"; how CTX can debit a non-custodial account is unresolved.
- **Internal:**
  - **`vault-withdraw`:** `withdraw(shares, [min], wallet)` pinned by `requireWithdraw` (`smart-wallet.ts:195-212`): vault = pinned, shares = all shares the app read, `from` = wallet, minimum ≥ RPC-read value × (1 − 1%) (`withdrawSlippageBasisPoints`, line 34). CTX computes its own minimum; the app only checks it is not lower.
  - **Vault deposit:** not initiated by the app.
  - **Fees and reserves:** CTX relayer is the source; the system key fee-bumps. The app does not inspect source, fee, sequence or footprint.
- **Added @7c694ca:**
  - **Pay split into sign then sponsor.** `SmartWallet.pay` (`smart-wallet.ts:134-149`) verifies and signs, returning `{expiryLedger, transfer, sponsor()}`; `PaymentSender.send` (`ctx/payment-sender.ts:48-89`) writes a `sending` record before sponsoring and maps 409/400/429 to states. A signed-but-unsponsored auth entry now sits in memory across an `await records.sending(...)`.
  - **Auto top-up from savings.** `SavingsTopUp.run` (`wallet/savings-top-up.ts:97-125`) withdraws `estimatedShares` (+1 retry) when the wallet is short, requiring ≥ 90 s left on the price window; failure modes leave USDC in the wallet ("funds are in your wallet").
  - **"Did it land" from chain events.** `transferLanded` (`payment-state.ts:93-107`) matches amount and, if recorded, muxed id; with `expected === null` any wallet → payee transfer counts. Ledger window `[expiry − 120, expiry + 1]` (`payment-search.ts:20-25`).
  - **Payouts / "on the way".** `ctx/payout.ts`, `ctx/account.ts`, `wallet/holdings.ts` (`onTheWayFrom`, `floorOf`, `shownUnit`) compute approximate totals from CTX account and payout records, filtered to this wallet's address.
  - **Cashback destination** (`account`|`savings`) set by the user via `PUT /users/{tid}` from `/orders/cashback`.
- **Value representations:** on chain i128 at 7 decimals (SAC balances, vault shares, vault value); CTX JSON decimal strings (`cardFiatAmount`, `paymentCryptoAmount`, `cashbackAmount`, denominations) and integer basis points (`userDiscount`, `link.userDiscountBasisPoints`); app `bigint` via `units.parse/format` (`stellar/units.ts`); display via `money.ts`, which converts to `Number` (`money.ts:16,40`).
- **Who can move money:** the device key (rule 1, restricted on chain by the factory's `device_allows`); the passkey (rule 0, full control, never used by this app after creation); the factory admin (can widen rule 1); CTX (cannot sign for the account); anyone holding the device key (a thief with biometrics; any same-origin script on web).

## 4. Trust boundaries & threat model

| Adversary | Capabilities | Goal |
|---|---|---|
| Unauthenticated internet user | Call `/login` and `/verify-email` for any email (no per-code attempt cap on CTX; `/login` 200 vs 201 leaks account existence); craft `loop://` and web URLs into any route with any params | Account takeover via CTX; push a signed-in user into a confusing route state |
| Authenticated customer | Any customer-role CTX call with their own token, including ones the app never calls (wallet link CRUD, transfers, 2FA, protected requests) | Reach another user's data (CTX IDOR guard: annex), pay once and claim twice, cashback without paying, set profile values the UI hides |
| Compromised or buggy CTX | Every JSON field the app reads: `BuiltTransaction`, wallet links, order amount and currency, codes, `redeemUrl`, `barcodeUrl`, merchant `info`, `website`, image URLs, `/me` lists, error bodies | Get a signature for a CTX-chosen amount, destination memo or call; point the app at a wallet the user does not control; inject a hostile URL; make funds unreachable |
| Lying Soroban RPC / on-path to RPC | Every simulation, ledger entry and tx status | Pass `verify()` for a wrong account; zero the withdraw floor; misreport tx outcome |
| Same-origin script on web (XSS, malicious dependency, browser extension) | `localStorage`, the IndexedDB CryptoKey (usable, not extractable), the live session | Steal the refresh token; sign pay or withdraw with no user gesture; read codes |
| Device adversary (lost phone, shared device, second Loop user, reinstall) | App UI, Keychain after reinstall, backups, screenshots, app switcher, clipboard | Read codes; use the session; as a second user overwrite the first user's device key |
| Supply chain | Code in the JS bundle (stellar-sdk, noble, passkeys, Expo modules) and install scripts | Swap destinations before signing; exfiltrate keys |
| Malicious factory admin | Factory config (`device_allows`) | Widen what a stolen device key can do |
| Insider with repo access | Change `network.ts` pins or `.env` at build | Repoint payee, verifier, wasm or vault; ship with no gate (no CI) |

- **Assets:** wallet funds; gift-card codes (number, PIN, and `redeemUrl`/`barcodeUrl`, which embed 10-year unauthenticated view tokens and are themselves bearer credentials); the device key; the passkey; the CTX session (rotating refresh token, 90-day TTL); PII (email, country, purchase history); availability of funds (a lost device key with no recovery path is a loss).
- **Boundaries:**
  1. CTX `BuiltTransaction` → `SponsoredCall.verify` + `require*` → device signature. The only place untrusted bytes become a signature.
  2. CTX wallet link → `SmartWallet.verify` (RPC) → wallet treated as the user's.
  3. CTX order and merchant fields → UI, `Image`, `ExternalLink`, `WebBrowser.openBrowserAsync`.
  4. Route params and deep links → CTX paths (`giftCard(id)` unencoded; `merchant(slug)` encoded).
  5. JWT payload → path segment (`userIdFrom`, `client.ts:383-386`, no validation).
  6. Build-time env → CTX base URL and Stellar network, chosen independently (`network.ts:70`, `client.ts:411-414`).
- **Sensitive data:**
  - Refresh token: native SecureStore `ctx.refreshToken` (`session/token-store.ts`), no biometric gate, survives uninstall on iOS; web `localStorage`.
  - Access token: memory.
  - Device secret: native SecureStore `device.signer.secret`, `requireAuthentication: true` (`device-signer.ts:11`), invalidated on biometric change; web non-extractable CryptoKey in IndexedDB, no user-presence gate.
  - Passkey: platform authenticator; public key and credential id go to CTX at deploy.
  - Codes: memory, rendered `selectable`, copied with 60 s expiry (iOS `localOnly`, Android `isSensitive`); capture blocked only while `GiftCardDetails` is mounted (`gift-card-details.tsx:16`), native only.
  - Email: sent to CTX; used as the passkey user name (`index.tsx:61`).

## 5. Invariants (with enforcement tiers)

Tiers: **chain** (contract-enforced; app code cannot bypass) > **runtime** (app check; a new path can skip it) > **test** > **convention**. No DB tier exists in this repo. **CTX** marks a check in spend-api: outside this repo's control, recorded so the audit knows what it leans on. Tier = weakest writer. Each tier below was checked by opening the enforcing code; "test: none" means no test asserts the failure case.

### INV-1 — Never sign a transaction that was not decoded and pinned locally
- **Statement:** every device signature is over `sha256(xdr(ScMap{account: wallet, context_rule_ids: [1], signature_payload: sha256(HashIdPreimage(auth entry, expiry, passphrase))}))`, recomputed locally, for a transaction with one `invokeHostFunction` op, one address-credential auth entry for this wallet, no sub-invocations, and an auth root call equal to the op's call.
- **Enforced by:** runtime `SponsoredCall.verify` (`wallet/sponsored-call.ts:22-75`, `authDigest` 78-98). The signer receives `call.digest`, never `built.digest` (`smart-wallet.ts:135-156`). CTX re-checks the call at sponsor time. Test: none.
- **Writers:** `signAndSponsor` is the only caller of `deviceSigner.sign`; `pay` and `withdraw` both reach it through `verify`. Tier: runtime.
- **Gaps:** outer transaction unchecked (fine for authorization). Expiry ledger matched to `built.expiryLedger` with no upper bound (CTX uses +60). The digest formula must match OZ stellar-accounts; a mismatch fails closed, but there is no known-vector test to catch a library change.
- **Keeping it:** any new intent adds a `require*` pin between `SponsoredCall.verify` and `signAndSponsor`; nothing else may call `deviceSigner.sign`.

### INV-2 — A pay signature moves only the quoted amount of the quoted token to the CTX payee
- **Statement:** `contract == SAC(order.paymentCryptoCurrency) ∧ method == transfer ∧ from == wallet ∧ base(to) == network.payee ∧ amount == units.parse(order.paymentCryptoAmount)`.
- **Enforced by:** runtime `requirePayment` (`smart-wallet.ts:165-180`) from `pay` (111-121); chain: rule-1 restriction via factory `device_allows` (not read by the app). Test: none.
- **Gaps:** the quote is a CTX field (RFC-1). Muxed id not pinned, although it is derivable from `paymentId`. `units.parse` throws on > 7 decimals (fail closed). Mainnet has no GBPLOOP token, so such an order fails closed.

### INV-3 — A withdraw signature burns only the requested shares into this wallet with ≤ 1% slippage
- **Enforced by:** runtime `requireWithdraw` (`smart-wallet.ts:195-212`), floor from `valueOf` (214-219) via RPC. Test: none.
- **Gaps:** floor source is the trusted RPC; DeFindex argument order and recipient semantics assumed, matching CTX's builder (`defindex/service.go:341-366`) but not checked against the vault source.

### INV-4 — The wallet in use runs pinned code and holds exactly the user's two signers
- **Statement:** `wasmHash == network.accountWasmHash ∧ rules == 2 ∧ rule0 = one permanent External signer via the WebAuthn verifier ∧ rule1 = one permanent External signer via the ed25519 verifier holding this device's key`.
- **Enforced by:** runtime `verify` (`smart-wallet.ts:71-90`, `requireSigner` 182-193), from `load` and `create`. CTX: nothing (annex). Test: none.
- **Gaps:** on `load` the passkey key is not compared (`requireSigner` skips the key when none is passed). Rule context type and policies not checked. Address not derived from the factory and `credentialId`, although CTX derives it that way and the factory is pinned. Single RPC. First matching link wins.

### INV-5 — Money arithmetic is exact
- **Enforced by:** runtime `units.parse` (regex, max 7 decimals), bigint compares in `require*`, bigint math in `Merchant.cashbackEstimate` (`ctx/merchant.ts:76-90`). Test: `money.test.ts` (display), `ctx/merchant.test.ts` (estimate rounding, non-positive amounts). No direct test of `units.parse`; its rejection is only exercised indirectly via `cashbackEstimate('abc')` (`merchant.test.ts:58-61`).
- **Gaps:** `money.ts:16,40` and `merchant.ts:73` use `Number` for display. `BigInt(this.cashbackBasisPoints())` throws if CTX ever sends a non-integer (CTX documents integer basis points).

### INV-6 — Each order is paid at most once
- **Enforced by:** CTX: sponsor records the payment tx id and returns 409 `ErrPaymentAlreadySubmitted` with `txId`; build requires payment status pending or part-paid. Chain: the auth nonce makes each signature single-use. Runtime: `paying` ref (`gift-card-purchase.tsx:48,178-199`, per component instance) and `canPay` (`payment-state.ts:66`). Test: `payment-state.test.ts` asserts the 409 → confirming mapping and `canPay` false once a tx id exists.
- **Tier:** CTX for the property; runtime in the app. Two tabs or devices each sign; only CTX stops the second.

### INV-7 — A session belongs to one user and leaves nothing behind
- **Statement:** after sign-out nothing from the previous user survives, and a new user on the device cannot affect the previous user's wallet.
- **Enforced by:** runtime, partial. `signOut` (`client.ts:211-214`) clears tokens; home clears wallet and balances (`index.tsx:110-116`). Orders state (`orders/index.tsx:19`) and shop profile state (`shop/index.tsx:25`) persist in mounted tabs. The device key is per install: `deviceSigner.create` deletes and replaces it (`device-signer.ts:30-32`), and CTX deploy ignores new keys on repeat. Test: none. **Effective tier: convention, and violated for the device key.**

### INV-8 — Refresh tokens rotate without losing the session

## 7. Tech-specific traps

1. **OZ smart-account digest is not the Soroban payload.** The device key signs `sha256(xdr(ScMap{account, context_rule_ids, signature_payload}))`; ScMap keys must be sorted. A library bump can change it.
2. **`TransactionBuilder.fromXDR` returns `FeeBumpTransaction` for fee-bump envelopes.** `sponsored-call.ts` rejects non-`Transaction`; CTX fee-bumps only after signing.
3. **`scValToNative` on a muxed address returns `M…`.** `accountOf` (`smart-wallet.ts:158-163`) strips the mux; a comparison that skips it pins nothing, and the stripped id is the order binding.
4. **Simulation reads are unauthenticated.** `soroban.read` simulates from a dummy source; the result is whatever the RPC says.
5. **`expo-secure-store` with `requireAuthentication`:** invalidated on biometric change; reads fail on cancel, lockout, timeout. Keychain items survive uninstall on iOS. Android backup follows the plugin's rules.
6. **WebCrypto Ed25519** needs a current browser; non-extractable keys stay usable by any same-origin code.
7. **`react-native-passkeys` returns SPKI DER.** `passkey.ts` takes the last 65 bytes; valid only for uncompressed P-256.
8. **Passkey RP id** differs between web (hostname) and native (`loopfinance.io`).
9. **`fetch` and `rpc.Server` have no default timeout.**
10. **expo-router params are decoded strings or arrays.** `useLocalSearchParams<{ id: string }>()` is a type assertion, not validation.
11. **`EXPO_PUBLIC_*` are inlined at build time and public;** a missing var becomes `''` here.
12. **`Number` in display** loses precision beyond 2^53.
13. **`BigInt(n)` throws on non-integer numbers.**
14. **React Compiler** memoizes automatically; code relying on callback identity or render-time ref mutation can behave differently.
15. **CTX refresh tokens rotate on every call; reuse inside 30 s revokes the new chain.**
16. **`node --test` runs `.ts` by type stripping:** no `@/` aliases, no enums or parameter properties, `.ts` import extensions. Wallet code imports `@/` and RN, which is why it has no tests.
17. **CTX signature expiry is 60 ledgers (~5 min).** A slow biometric prompt between build and sponsor fails on chain, not in the app.
18. **`@react-native-async-storage/async-storage` is unencrypted** on native and is `localStorage` on web; anything stored there (wallet pin, sent-payment records, favourites) is readable and writable by device backup, root, or same-origin script.
19. **`navigator.locks` exists only on web** (and not in every browser/WebView); `exclusive` silently degrades to no lock.
20. **OIDC ID tokens without a nonce** are replayable bearer credentials for their lifetime; CTX enforces the nonce only when one is sent.
21. **`expo-updates` with `checkAutomatically: NEVER`** runs only when the app calls it; `reloadAsync` mid-flow drops all in-memory state (signed-but-unsponsored payments, generation counters).
22. **`expo-local-authentication` error codes** (`not_enrolled`, `passcode_not_set`, `lockout`) differ per platform; treating any as success is a policy decision to check.
23. **Sentry `beforeSend` returns the event to send**; a scrubber that throws or returns the original on unknown shapes leaks.
24. **`rpc.Server.getEvents`** only covers the RPC's retention window (~7 days on most providers) and pages by limit; an empty result is not proof of absence.

## 8. Recurring failure classes

- **RFC-1 — Upstream data compared to upstream data.** A pin that checks a CTX field against another CTX field proves consistency, not correctness (amount pin; wallet address). For each `require*`, ask where the expected value came from.
- **RFC-2 — Fail-open guards.** Checks that skip when an optional argument is missing (`requireSigner` without a key), or early returns that lead to a destructive default (`load` returns null → `create` overwrites the key).
- **RFC-3 — Platform split weaker on one side.** Diff each `.ts`/`.web.ts` pair for security properties.
- **RFC-4 — Secrets in visible text or URLs.** Error bodies rendered verbatim; codes `selectable`; bearer tokens inside `redeemUrl`/`barcodeUrl`.
- **RFC-5 — Per-user state outliving the user.** Module singletons, mounted tab state, device key.
- **RFC-6 — Strings as protocol.** CTX error names and message text matched literally.
- **RFC-7 — Docs as claims.** `PRODUCT.md`, design notes, commit messages.
- **RFC-8 — Unbounded waits.** Polls, fetches, prompts without timeout or cap.
- **RFC-9 — Unencoded identifiers in paths.** Each new CTX path built from a route param or CTX field; `merchant()` encodes, `giftCard()` does not.
- **RFC-10 — Compatibility fallbacks that widen authority.** Paths kept for old installs (shared device key fallback, first-use wallet pin, `expected === null` landing match, `navigator.locks` absent → no lock). Each fallback is where the strict check silently becomes the lax one.
- **RFC-11 — Local records treated as truth.** AsyncStorage/`localStorage` records (sent payments, wallet pin, favourites) steer money UI decisions ("already paid", "this is your wallet"); ask what happens when they are missing, stale, from another user, or forged.
- **RFC-12 — Sign now, act later.** A signature or reload request created in one step and consumed after awaits (`SignedPayment.sponsor`, `ReloadGate`); look for paths that drop, double-run, or outlive the user/session.
- **RFC-13 — Retries that are not idempotent upstream.** Network-error retries of CTX calls that rotate state (`/refresh-token`) or create resources (`POST /gift-cards`, sponsor).
