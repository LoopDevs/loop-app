## 1. Architecture at a glance

- **Stack:** TypeScript strict, Expo SDK 58, React 19 with the React Compiler, React Native, react-native-web, expo-router with typed routes. Chain: `@stellar/stellar-sdk` (Soroban RPC and XDR), `@noble/curves` (ed25519 native; p256 verify in `wallet/passkey-assertion.ts`), WebCrypto Ed25519 (web), `react-native-passkeys` (create and assert). Storage: `expo-secure-store` (native), AsyncStorage (unencrypted native, `localStorage` web), IndexedDB (web key). Also `@sentry/react-native`, `expo-updates`, `expo-local-authentication`, Apple and Google sign-in. Tests: `node --test` via `test/alias-loader.mjs`, which resolves `@/` so RN-free modules that use aliases are testable.
- **Topology:**
  - One client process per device or browser tab. Web is a static export (`app.json` `web.output: "static"`) on Cloudflare Pages with three edge functions: `/api/region`, `/api/catalog/merchants`, `/api/catalog/image`.
  - In-process guards (refresh single-flight, `InFlightPayments`, `OneTapBuy.running`, poll generations, `ReloadGate`) are per process. Cross-tab guards exist on web only via `navigator.locks` (`token-store.web.ts` `exclusive`, `ctx/payment-lock.web.ts`). Native `paymentLock` is an in-memory `memoryLock`; native `tokenStore.exclusive` is `holdCriticalReload` only, no lock. Two devices stay independent actors; only CTX serialises them.
  - A WebSocket to CTX `/ws` (`ctx/client.ts` `watchOrder`, `watchAccount`) pushes order and account events; polling remains as the fallback.
- **Environment:** `src/environment.ts` `LoopEnvironment` reads `EXPO_PUBLIC_LOOP_ENV` (`staging`|`production`; anything else throws) and fixes the CTX URL, Stellar network and client id together. `storageKey(key)` suffixes the env name so staging and production state do not mix on one device. `eas.json`: development and preview → staging, production → production.
- **Authority per entity:**
  - **CTX spend-api** (`src/ctx/client.ts`): users, sessions, merchants, gift-card orders, payments (crypto and Plaid bank), cashback ledger, payouts, wallet links, sponsoring.
  - **Stellar (Soroban):** the user's OZ smart account, token balances (SACs), DeFindex vault shares. Read by RPC simulation (`src/stellar/soroban.ts`); the app never submits transactions.
  - **Device:** refresh token, device signer key, wallet pin, sent-payment and pending-withdrawal records. Access token in memory.
  - **Cloudflare edge:** the signed-out catalog view and merchant images (cached copies of CTX data).
- **External integrations and trust:**
  - **CTX** (`loopEnvironment.ctxApiUrl`): semi-trusted. Sponsor, relayer, pricer, order book, bank-payment initiator. Builds every transaction the user signs. Design rule: never sign what CTX built without decoding and pinning it (`wallet/sponsored-call.ts`, `wallet/smart-wallet.ts`, `wallet/device-link.ts`). Trusted for prices, order state, cashback, codes; not trusted for destinations, call shape, wallet code or URLs. CTX re-derives the call at sponsor time (annex), which protects against a broken app, not a hostile CTX.
  - **CTX rates** (`ctx/rates.ts`, `https://rates.ctx.com`): the quote `BuyPrice.check` compares orders against. Same operator as the order book: independent of the endpoint, not of the party (RFC-1).
  - **Soroban RPC** (`stellar/network.ts` `rpcUrls`): two providers per network; `soroban.ts` fails over on transport errors only, with no cross-check. Every chain-side check (wasm hash, rules, vault value, tx outcome, transfer events) reads through whichever answers.
  - **Pinned contracts** (`stellar/network.ts`): account wasm hash, WebAuthn and ed25519 verifiers, payee G-address, token SACs (XLM, USDC, EURC, GBPLOOP), vaults (testnet USDC; mainnet USDC and GBPLOOP), `usdcIssuer` (read by `wallet/pay-request.ts`). `factory` and `usdc` are pinned; re-check whether anything reads them.
  - **Cloudflare edge** (`edge/catalog.ts`, `edge/region.ts`): trusted by the signed-out web and by every client for images. Unauthenticated, cached.
  - **Plaid** (via CTX): a CTX-returned `paymentUrl` opened in the in-app browser.
  - **OS services:** passkey providers, biometrics, clipboard, screen capture, in-app browser, Apple/Google identity.
  - **Sentry** (`EXPO_PUBLIC_SENTRY_DSN`), **EAS Update** (signed bundles), **Friendbot** (testnet).
- **Seams where interaction bugs concentrate:**
  1. `ctx/client.ts` → `wallet/smart-wallet.ts` → `wallet/sponsored-call.ts` (or `device-link.ts`) → device signer or passkey → CTX sponsor. Every `BuiltTransaction` field crosses here.
  2. Key lifecycle: `device-key.ts`, `device-signer(.web).ts`, `passkey.ts`, `wallet-pin.ts`, `wallet-creation.ts`, CTX deploy (idempotent per credential id, ignores new keys), `rotate_device` on chain.
  3. Buy pipeline: `components/gift-card-purchase.tsx` ⇄ `ctx/one-tap-buy.ts` ⇄ `ctx/payment-sender.ts` ⇄ `ctx/payment-state.ts` ⇄ CTX order status ⇄ `/ws` events ⇄ chain transfer events. Five sources of truth for "did I pay".
  4. Session: `session/token-store(.web).ts` ⇄ `session/session-auth.ts` ⇄ CTX rotation with a 30 s reuse window; the socket authenticates once at connect.
  5. Platform splits: web holds weaker key custody, token storage and socket auth behind the same interfaces.
  6. Edge ⇄ app: `EXPO_PUBLIC_CATALOG_URL` responses and rewritten image URLs feed the same `Merchant` model as signed-in CTX responses.

## 3. Money flows

MNY is the top-weighted dimension. Every flow ends in a CTX call, a CTX-built chain transaction, or a CTX-initiated bank payment.

- **Ingress to the wallet:**
  - **External deposit** to the smart-account C-address, offered as a `web+stellar:pay` request for USDC (`wallet/pay-request.ts`). Many exchanges cannot send to a C-address.
  - **Cashback:** a CTX ledger credit first; on chain only as a threshold payout. With `cashbackDestination: savings` the payout is a gift of vault shares (annex). The app displays ledger and payout records (`ctx/account.ts`, `ctx/payout.ts`, `wallet/holdings.ts`).
  - **Friendbot** (testnet).
- **Egress:**
  - **`pay`:** SAC `transfer(wallet, M-address, amount)`, built by CTX. Pinned by `smart-wallet.ts:requirePayment`: contract = SAC for `paymentCryptoCurrency`, `transfer`, `(address, address, i128)`, payer = wallet, base of `to` = `network.payee`, `to` = `giftCard.paymentCryptoAddress`, amount = `units.parse(paymentCryptoAmount)`. The muxed destination is pinned, but to CTX's own field, not to an id derived from `paymentId` (RFC-1).
  - **Bank pay (GB):** no chain leg. CTX returns a Plaid `paymentUrl` (UK/EU) or executes a VRP immediately; the app opens the URL unchecked. CTX picks the method from config, not from the app (annex).
  - **Cash-out:** mock-up only; nothing leaves.
  - **Refund / reversal:** operator-triggered on CTX; the reversal is a CTX ledger transfer, never a chain debit (annex).
- **Internal:**
  - **`vault_withdraw`** (savings, and top-up before pay): `withdraw(i128 shares, vec<i128>[min], address)` pinned by `smart-wallet.ts:requireWithdrawal` (vault, shares, owner), floor `Holdings.floorOf(valueOf)` from RPC.
  - **`rotate_device`:** passkey-signed (rule `[0]`) call on the wallet itself; pinned by `DeviceRotation.require` (contract = wallet, method, one arg = new key).
  - **Fees and reserves:** CTX relayer; the system key fee-bumps. The app does not inspect source, fee, sequence or footprint.
- **Order creation as money:** `OneTapBuy` creates up to two orders per tap. `OrderKeys` sends an `Idempotency-Key` that CTX does not implement (annex). When the answer to `POST /gift-cards` is lost (timeout or network error, not a CTX refusal), `ctx/client.ts:placedOrder` adopts the newest unpaid order for that merchant that matches the request and was created since it was asked, allowing 5 min of clock skew (`OrderRequest.placed`); an order CTX creates after that lookup, and the one-tap re-create path, can still leave duplicate unpaid orders.
- **Value representations:** chain i128 at 7 decimals; CTX JSON decimal strings and integer basis points; app `bigint` via `stellar/units.ts`; display via `money.ts` (`Number`); quote check in basis points (`ctx/buy-price.ts`, 100 bps tolerance).
- **Who can move money:** the device key (rule 1, restricted on chain by the factory's `device_allows`); the passkey (rule 0, full control; the app uses it for `rotate_device`); the factory admin; CTX (cannot sign for the account); anyone holding the device key (a thief with biometrics; any same-origin script on web).

## 4. Trust boundaries & threat model

| Adversary | Capabilities | Goal |
|---|---|---|
| Unauthenticated internet user | `/login`, `/verify-email` (CTX: 20 min expiry, 5-attempt lock); craft `loop://` and universal links into any route; hit the edge functions with any query | Account takeover via CTX; abuse the image proxy or poison the catalog cache |
| Authenticated customer | Any customer-role CTX call, including ones the app never calls (wallet link CRUD, `send`, recovery start, payment methods) | Reach another user's data, pay once and claim twice, duplicate orders |
| Compromised or buggy CTX | Every JSON field: `BuiltTransaction`, wallet links, order amount/currency/address, rates, codes, `redeemUrl`, `barcodeUrl`, `paymentUrl`, merchant text and images, socket events, error bodies | A signature for a CTX-chosen amount, destination or call; a hostile URL in the in-app browser; a wallet the user does not control |
| Lying Soroban RPC (either provider) | Every simulation, ledger entry, event and tx status | Pass `verify()` for a wrong account; zero the withdraw floor; fake "paid" or "rotated" |
| Same-origin script on web | `localStorage` (refresh token, pin, records), the IndexedDB CryptoKey, the live session | Steal the session; sign with no gesture; forge the wallet pin |
| Device adversary | App UI, backups, screenshots, app switcher, clipboard | Read codes; use the session |
| Cloudflare / edge config | Catalog responses, image bytes, response headers, CSP | Serve a lookalike catalog or image; drop CSP |
| Supply chain | JS bundle dependencies, install scripts, GitHub Actions | Swap destinations before signing |
| Insider with repo / CI access | `network.ts` pins, `environment.ts`, release workflow, OTA signing key | Repoint payee or verifier; ship a signed bundle |

- **Assets:** wallet funds; gift-card codes and bearer URLs (`redeemUrl`/`barcodeUrl` carry 10-year view tokens); the device key; the passkey; the CTX session (90-day rotating refresh token); bank details typed into cash-out; PII (email, legal name, country, purchases); the OTA signing key (CI secret).
- **Boundaries:**
  1. CTX `BuiltTransaction` → `SponsoredCall.verify` + `require*` → device or passkey signature.
  2. CTX wallet link → `WalletPin.choose` → `WalletRules.check` (RPC) → wallet treated as the user's.
  3. CTX order, merchant and payment fields → UI, `Image`, `ExternalLink`, `openBrowserAsync`.
  4. Route params and universal links → CTX paths (`giftCard(id)` and `merchant(slug)` encode; wallet ids from CTX do not).
  5. JWT payload → path segment (`client.ts:userIdFrom`, no validation).
  6. Edge: internet query → `CatalogQuery` whitelist → CTX; image `src` → S3 prefix check → fetch.
  7. `/ws` socket: native sends auth headers; the browser `WebSocket` constructor ignores them. CSP `connect-src` lists only `https:` origins (check whether target browsers let them match `wss:`).
  8. Build/CI: `environment.ts` constants, release workflow ref gate, OTA code signing.
- **Sensitive data:**
  - Refresh token: native SecureStore via `InstallScopedToken` (wiped when the AsyncStorage install marker is missing, so a reinstall drops it); web `localStorage` `ctx.refreshToken` (not env-scoped).
  - Device secret: native SecureStore `device.signer.<userId>`, `requireAuthentication: true`; web non-extractable CryptoKey in IndexedDB.
  - Wallet pin: native SecureStore, web AsyncStorage (`wallet-pin.ts` `pinStorage`).
  - Codes: memory, copied with expiry, capture blocked while details are mounted (native).
  - Cash-out bank details: component state only (mock).

## 5. Invariants (with enforcement tiers)

Tiers: **chain** > **runtime** > **test** > **convention**. **CTX** marks a check in spend-api, outside this repo's control. Tier = weakest writer. "Test: none" means no test asserts the failure case. All cites @95aec37.

### INV-1 — Never sign a transaction that was not decoded and pinned locally
- **Statement:** every signature is over a locally recomputed OZ digest (`sponsored-call.ts:authDigest`) for one `invokeHostFunction` op with one address-credential auth entry for this wallet, no sub-invocations, auth call = op call, expiry = `built.expiryLedger` within `(latest, latest + 120]`, and `contextRuleIds` equal to the rule ids the intent expects (`[1]` device, `[0]` passkey).
- **Enforced by:** runtime `SponsoredCall.verify(built, wallet, ruleIds, latestLedger)`; device path through `smart-wallet.ts` (`pay`, `signWithdrawal`), passkey path through `device-link.ts:DeviceLink.add`. CTX re-checks the call at sponsor time. Test: `sponsored-call.test.ts` (check whether it pins a known OZ digest vector or only round-trips the app's own `authDigest`).
- **Keeping it:** any new intent adds a `require*` pin between `verify` and signing; nothing else may call `deviceSigner.sign` or a passkey assertion for a CTX-built payload.

### INV-2 — A pay signature moves only the quoted amount of the quoted token to this order's address
- **Statement:** `contract == SAC(paymentCryptoCurrency) ∧ method == transfer ∧ from == wallet ∧ base(to) == network.payee ∧ to == paymentCryptoAddress ∧ amount == units.parse(paymentCryptoAmount)`, and the order matches the request (`OrderRequest.matches`: merchant, currency, fiat amount) and an independent USD quote within 100 bps (`BuyPrice.check`).
- **Enforced by:** runtime `requirePayment`, `OrderRequest.matches` (`ctx/client.ts:orderGiftCard`), `BuyPrice.check` (`ctx/one-tap-buy.ts`). Chain: rule-1 `device_allows`. Tests: `order-request.test.ts`, `buy-price.test.ts`, `one-tap-buy.test.ts`; for `requirePayment` itself, check `smart-wallet.test.ts`.
- **Gaps:** destination and quote are CTX data (RFC-1); the rates feed is CTX's. Muxed id not derived from `paymentId`.

### INV-3 — A withdraw signature burns only the requested shares into this wallet above a floor
- **Enforced by:** runtime `requireWithdrawal` (vault, shares, owner), floor `Holdings.floorOf(valueOf)`; `signWithdrawal` under `holdCriticalReload`. Tests: `savings.test.ts`, `savings-top-up.test.ts`, `holdings.test.ts`.
- **Gaps:** floor source is the RPC being trusted; GBPLOOP vault on mainnet only (`network.ts` `vaults`); CTX needs the chain-qualified currency (annex, unverified).

### INV-4 — The wallet in use runs pinned code, holds exactly the user's two signers, and is the one this user pinned
- **Statement:** `wasmHash == pinned ∧ rules == 2 ∧ rule0 = one permanent External WebAuthn signer (= pinned passkey key) ∧ rule1 = one ed25519 signer`, and the address is the user's pinned address; `thisDevice` is `linked` only when rule 1 holds this device's key.
- **Enforced by:** runtime `WalletRules.check`, `WalletPin` (`choose`, `admits`, `pinCreatedHere`, `pinConfirmed`, `requireCurrentUser`), `SmartWallet.load`/`create`. Pin in SecureStore on native. Tests: `wallet-rules.test.ts`, `wallet-pin.test.ts`, `smart-wallet.test.ts`.
- **Gaps:** trust-on-first-use: unpinned, `choose` takes the first usable link and the passkey key is not compared. Web pin is in `localStorage`. Address not derived from factory + `credentialId`. Rule policies not checked.

### INV-5 — Money arithmetic is exact
- **Enforced by:** runtime `units.parse` (max 7 decimals), bigint compares in `require*` and `Merchant.cashbackEstimate`, basis-point math in `BuyPrice`. Tests: `money.test.ts`, `merchant.test.ts`, `buy-price.test.ts`, `amount-input.test.ts`.
- **Gaps:** `money.ts` display via `Number`; `OrderRequest.matches` compares a truncated fiat amount (check the truncation cannot accept a different order).

### INV-6 — Each order is paid at most once, and a tap creates only the orders it means to
- **Enforced by:** CTX: one in-flight sponsored tx per payment (`ErrPaymentAlreadySubmitted`), `pay` only on `pending`. Chain: auth nonce. Runtime: `InFlightPayments`, `paymentLock` (`memoryLock` native, `navigator.locks` web), `SentPayments`, `canPay`, `OneTapBuy.running`, `maxOrders = 2`. Tests: `payment-sender.test.ts`, `sent-payments.test.ts`, `in-flight-payments.test.ts`, `payment-state.test.ts`, `one-tap-buy.test.ts`, `memory-lock.test.ts`.
- **Gaps:** CTX ignores `Idempotency-Key`, so order creation is not idempotent upstream (RFC-13, RFC-14); the lost-answer recovery in `ctx/client.ts:placedOrder` closes the user-retry path only when CTX created the order before the lookup. `transferMatches(value, null)` is fail-open. Cross-device double pay rests on CTX alone.

### INV-7 — A session belongs to one user and leaves nothing behind
- **Enforced by:** runtime: per-user device key `device.signer.<userId>` (regex-validated id; the legacy shared-key fallback is gone), per-user pin keys, `WalletPin.requireCurrentUser`, session generation counter and `useSessionOwner`; `sign-in.tsx` signs out a different email first. Tests: `device-key.test.ts`, `wallet-pin.test.ts`, `session-owner.test.ts`.
- **Gaps:** `SentPayments` and pending-withdrawal records are keyed by payment id / address, not user; favourites cleared only on a deletion request; check the web device-signer for any surviving shared-key read.

### INV-8 — Refresh tokens rotate without losing the session
- **Enforced by:** runtime `SessionAuth` single-flight and generations; web `navigator.locks`; native no lock (one process). CTX: rotation with a 30 s reuse window. Tests: `session-auth.test.ts`, `session-tokens.test.ts`.
- **Gaps:** `sendRefreshToken` retries once on a non-`CtxError` with the same token (reuse inside CTX's window); `sessionRequest` replays the original request after a refresh, including `POST /gift-cards`.

### INV-9 — Gift-card codes reach only their owner and do not leak from the device
- **Enforced by:** CTX ownership on `GET /gift-cards/:id`; socket payloads carry no secrets. Runtime: capture block while details are mounted, switcher blur, clipboard expiry, barcode shown only on reveal, `redeemUrl` opened only if `externalUrl.isWeb`.
- **Gaps:** bearer view tokens in URLs; `isWeb` allows any http(s) host; web has no capture protection.

### INV-10 — Pinned chain constants match the selected network, and CTX and network are paired
- **Enforced by:** runtime pairing: `LoopEnvironment` fixes CTX URL + network per env and throws on anything else. Pins vs chain: convention (nothing checks the pins against the live network in CI). Whether CTX's payee equals `network.payee` is CTX config.

### INV-11 — CTX requests carry only the caller's identity and well-formed paths
- **Enforced by:** CTX IDOR guard. Runtime: `giftCard(id)` and `merchant(slug)` encode. Not enforced: wallet ids in `/wallets/${walletId}/stellar/*` (CTX-supplied); `userIdFrom` unvalidated.

### INV-12 — Profile updates send only whitelisted values
- **Enforced by:** runtime `Profile.nextUpdate` against CTX company lists; `UserUpdate` = country | stableCurrency | cashbackDestination | legalName. CTX refuses `stableCurrency` changes once set. Test: `profile.test.ts`.

### INV-13 — App lock covers the app whenever it is on and stale
- **Enforced by:** runtime `AppLock` (`session/app-lock.ts`): locks on load failure, after 5 min background or a clock jump; unlocks on success **or** `not_enrolled`/`passcode_not_set`. Web: no-op. Test: `app-lock.test.ts`. A UI cover, not a key gate.

### INV-14 — Error reports carry no secrets or PII
- **Enforced by:** runtime `SentryScrubber` with an `allowKeys` whitelist, `sendDefaultPii: false`, `ctxReportMessage` status + name only, `UnexpectedResponse` reports from `ctx-response.ts`. Tests: `sentry-scrubber.test.ts`, `ctx-report.test.ts`, `signing-report.test.ts`.

### INV-15 — A JS bundle swap never interrupts a pay and never runs code the release did not sign
- **Enforced by:** runtime: `expo-updates` code signing (`app.json` `updates.codeSigningCertificate`, rsa-v1_5-sha256) and `ReloadGate`/`holdCriticalReload` around pays, sign-in and withdrawals. CI: `release.yml` publishes production only from `v*` tags and checks the certificate and project id. Tier: runtime (was convention).

### INV-16 (new) — A device is linked only by a passkey-signed rotation the app pinned
- **Statement:** `rotate_device` is signed by the passkey (rule `[0]`), the call is the wallet's own `rotate_device(newDevicePublicKey)` with the key this device just created, and the assertion is a valid `webauthn.get` over the digest.
- **Enforced by:** runtime `DeviceLink.add` → `SponsoredCall.verify(…, [0])` → `DeviceRotation.require` → `PasskeyAssertion.requireSigned` (type, challenge, p256 verify). Chain: rule-0 WebAuthn verifier. Tests: `device-link.test.ts`, `device-rotation.test.ts`, `passkey-assertion.test.ts`.
- **Gaps:** `requireSigned` checks neither `origin` nor `rpIdHash`; the chain verifier decides. CTX stores no device key, so nothing off chain records the rotation.

### INV-17 (new) — Untrusted URLs open only on allowed schemes and hosts
- **Enforced by:** runtime `externalUrl.isWeb` for `redeemUrl`; edge `CatalogImage` S3 prefix + width whitelist; CSP from `src/ops/content-security-policy.ts` injected at build (`scripts/content-security-policy.ts`). **Not enforced:** bank `paymentUrl` (`gift-card-purchase.tsx`, `openBrowserAsync`), merchant `website`, the `CatalogImage` fallback `fetch(image.src)` (prefix-checked first; check redirects).

### INV-18 (new) — Signed-out catalog requests reach CTX only with whitelisted parameters
- **Enforced by:** runtime `edge/catalog.ts:CatalogQuery` (keys `enabled, order, country, name, ids, category, page, perPage, slug`, ≤ 512 chars each). Tests: `edge/*.test.ts`. CTX treats several of these as regexes (annex), so a whitelisted key still carries a regex.

## 7. Tech-specific traps

1. **OZ smart-account digest is not the Soroban payload.** Sorted ScMap `{account, context_rule_ids, signature_payload}`; a library bump can change it.
2. **`TransactionBuilder.fromXDR` returns `FeeBumpTransaction` for fee-bump envelopes.**
3. **`scValToNative` on a muxed address returns `M…`.** Strip and compare the id deliberately (`muxedIdOf`).
4. **Simulation reads are unauthenticated;** with two RPCs, failover takes whichever answers.
5. **`expo-secure-store` with `requireAuthentication`** is invalidated on biometric change; Keychain survives uninstall (the install marker handles this for the token only).
6. **WebCrypto Ed25519** non-extractable keys stay usable by any same-origin code.
7. **`react-native-passkeys` returns SPKI DER;** assertions return DER signatures that must be low-S compact for the verifier.
8. **WebAuthn assertions bind origin and rpId in `clientDataJSON` and `authenticatorData`;** checking only type and challenge leaves those to the verifier.
9. **Passkey RP id:** `PasskeySite.forHost` maps web hosts to `loopfinance.io` except localhost; staging hosts must be associated.
10. **expo-router params are decoded strings or arrays;** the generic is a type assertion.
11. **`EXPO_PUBLIC_*` are inlined at build time and public.**
12. **`Number` in display** loses precision beyond 2^53; **`BigInt(n)`** throws on non-integers.
13. **React Compiler** memoizes automatically.
14. **CTX refresh tokens rotate on every call; reuse inside 30 s revokes the new chain.**
15. **CTX signature expiry is 60 ledgers (~5 min).**
16. **AsyncStorage is unencrypted** on native and is `localStorage` on web.
17. **`navigator.locks`** exists only on web; native `memoryLock` is per process.
18. **OIDC ID tokens without a nonce** are replayable for their lifetime.
19. **`expo-updates` `reloadAsync`** drops in-memory state; code signing protects only builds that embed the certificate.
20. **`expo-local-authentication` error codes** differ per platform.
21. **`rpc.Server.getEvents`** covers only the retention window.
22. **The browser `WebSocket` takes no headers.** RN accepts a third options argument with headers; the browser ignores it, so auth must travel in the URL, a subprotocol, a first message or a cookie.
23. **CSP and `wss:`:** CSP Level 3 lets an `https:` source match `wss:` on the same host; older engines need an explicit `wss:` source.
24. **Cloudflare cache keys** include the full URL by default; a whitelist that drops unknown keys upstream must also keep them out of the cache key, or junk queries fragment or share entries.
25. **CTX regex filters:** `slug`, `name`, `ids`, `country` on `GET /merchants` are regexes; a bare value is a partial match.
26. **Headers CTX does not implement** (`Idempotency-Key`) give no protection, however carefully the client generates them.

## 8. Recurring failure classes

- **RFC-1 — Upstream data compared to upstream data.** Destination = `paymentCryptoAddress`; quote = CTX rates; wallet address = CTX link. For each `require*`, ask where the expected value came from.
- **RFC-2 — Fail-open guards.** Checks that skip when an optional argument is missing (`transferMatches(…, null)`, unpinned passkey key).
- **RFC-3 — Platform split weaker on one side.** Diff each `.ts`/`.web.ts` pair; include the socket (headers vs none) and the token store (env-scoped vs not).
- **RFC-4 — Secrets in visible text or URLs.** Codes; bearer URLs; bank details in mock forms.
- **RFC-5 — Per-user state outliving the user.** Records keyed by payment id or address.
- **RFC-6 — Strings as protocol.** CTX error names and message text.
- **RFC-7 — Docs as claims.** `PRODUCT.md`, marketing pages, commit messages.
- **RFC-8 — Unbounded waits.** Bounded by `Deadline` and expiry polls; check new loops.
- **RFC-9 — Unencoded identifiers in paths.** Wallet ids.
- **RFC-10 — Compatibility fallbacks that widen authority.** TOFU pin, `navigator.locks` absent, image proxy fallback fetch.
- **RFC-11 — Local records treated as truth.** Sent payments, pending withdrawals, wallet pin, install marker.
- **RFC-12 — Sign now, act later.** `SignedPayment.sponsor`, passkey rotation then sponsor, `ReloadGate`.
- **RFC-13 — Retries that are not idempotent upstream.** `/refresh-token`, `POST /gift-cards`, one-tap re-create, sponsor.
- **RFC-14 (new) — Client controls an upstream does not honour.** Headers, fields or arguments the app sends that the receiver ignores (`Idempotency-Key`, socket headers in a browser). Verify each control on the receiving side.
